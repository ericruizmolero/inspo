---
title: Borrar un espacio no deja nada suyo, salvo el gasto de IA, y exportarlo es un JSON que baja su propietario
date: 2026-10-10
status: vigente
kind: desarrollo
---
**Contexto.** Issue #35: no se podía llevarse los datos de un espacio, y borrar un equipo dejaba cosas sueltas. El borrado iba por el endpoint de Better Auth con dos ganchos que solo quitaban miniaturas y adjuntos de comentarios; quedaban las lápidas de la biblioteca (sin clave ajena), los avisos de `capture_claim` y `rate_limit` que llevan el id en la clave, las sesiones con el espacio abierto y el resto de ficheros (media, textos, marca, capturas del porqué).

**Decisión.** Una función borra (`deleteWorkspace`, `lib/workspace-delete.ts`): una transacción que borra la fila de `organization` (sus claves ajenas arrastran el resto), después las lápidas que escribe esa cascada, los `capture_claim` `system:<id>|…` y `brand:<id>|…`, los contadores `app:…:<id>` y el espacio abierto de cada sesión; luego los ficheros por prefijo (`inspo/<id>/` e `inspo/design-why/<id>/`) y vuelve a listar para saber que no queda nada. Se puede repetir: la segunda vez no encuentra filas y acaba con los ficheros (`npm run workspace:delete -- <id> --apply`). El endpoint de Better Auth está apagado (`disableOrganizationDeletion`); la interfaz usa la acción `deleteTeam`. El espacio personal no se borra. El gasto de IA se queda: `ai_usage.organization_id` pasa a null y `organization_name` guarda el nombre, escrito por un trigger `BEFORE DELETE` en `organization` (migración 0038), así que vale para cualquier camino que borre. Exportar es un JSON con un tipo (`WorkspaceExport`, `version: 1`, `lib/workspace-export.ts`) que baja el propietario desde Ajustes › Espacio (`GET /api/workspace/export?id=`): fichas, proyectos, sistema, comentarios, revisiones, miembros con su correo y gasto de IA. Sin embeddings, estado de etiquetado, cachés del modelo, tokens de enlaces compartidos ni hashes de llaves; los ficheros van como su ruta `/api/files/…`.

**Por qué.** El issue lo pide así: "con las relaciones ya arregladas es una sola operación, más limpiar sus archivos en R2", y "el histórico de gasto de IA no se borra con el workspace, se desliga y se guarda el nombre, porque lo necesitamos para la contabilidad". Que el nombre lo escriba el trigger al borrar, y no cada llamada al modelo, es de Claude: un solo sitio que escribe, ninguna consulta de más por llamada, y el nombre que queda es el último, el que conoce la contabilidad. No hay filas viejas que rellenar: hasta ahora la cascada las borraba.

**Cómo aplicarlo.** Una tabla nueva con `organization_id` lleva clave ajena con `cascade` (o `set null` si tiene que sobrevivir). Una clave de texto o un prefijo de storage nuevo que lleve el id de un espacio entra en `deleteWorkspace` en el mismo trabajo. `npm run check:workspace-delete` (también en CI) recorre todas las tablas con `organization_id` desde `information_schema` y falla si alguna guarda una fila del espacio borrado. Un campo nuevo en el export no cambia la versión; cambiar o quitar uno sí.
